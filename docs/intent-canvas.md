# 意图画布（Intent Canvas）实现说明

> 本文描述当前插件源码的能力与边界，不把设计设想、实验推论、性能目标或工期估算当成验收结果。实际安装与浏览器验证状态以交付记录为准。

## 0. 一句话

装在 Harness 内的可寻址 SVG 画布：人通过页面、AI 通过工具，提交同一套文档操作。图元、笔迹、批注与待确认事项具有稳定 id；版本号用于避免并发编辑静默覆盖。

## 1. 设计目标

- 用元素 id 与数字几何减少指代歧义。
- 用 `pending` 表达待确认意图，不以绘图手势默认为语义授权。
- 把自由笔迹纳入操作与撤销体系。
- 让人和 AI 使用同一个操作引擎，但由 Host 区分可信的人类入口与 AI 入口。

这些是产品目标，不是已完成用户实验或效果评估的结论。

## 2. 实现范围与验证边界

当前源码包含依赖较少的操作引擎、引擎测试和 React Client。Client 使用 Harness 模块加载器，不是独立站点或 iframe。

已执行的检查包括引擎自动化测试、Client 语法检查和模拟模块加载/样式/槽位注册检查。模拟检查不能替代真实 Harness 页面中的加载、主题、焦点与指针交互验收。尚未做有依据的帧率、延迟、token 成本或大文档基准测试。

## 3. 状态原则

1. 文档状态由 Host 维护并通过同一操作引擎修改；渲染只是投影。
2. 元素 id 由引用、批注和操作共同使用；`update` 不允许更换 id 或 kind。
3. 一个成功批次是一个撤销步骤；进行中的鼠标轨迹不是逐点文档操作。
4. 人与 AI 都可编辑共享文档，但咨询批准必须来自可信的人类入口。
5. 原子批次与版本检查优先于最后写入者覆盖。

## 4. 架构与接入

### 4.1 Harness Client

- 模块 id：`@local/intent-canvas`。
- 通过 `slots.inject` / `slots.register` 注册 `main`，key 为 `canvas`。
- 侧栏使用 `sidebar.panellist`，id 为 `canvas`；打开按钮调用 `layout.selectPanel('canvas')`。
- React 来自模块加载器；服务通过 `ctx.get` 获取。
- 使用 Host 的 locale 服务和 `--dsw-alias-*` 主题变量；标签覆盖中英文。
- 样式由主面板渲染的 React `<style>` 承载，随面板卸载移除；不依赖未提供的 `host` 或 `styles` 模块。

具体 Builtin 名称与槽位表现仍须与安装环境核对，不能仅凭模拟加载认定页面集成完成。Host 传输与实际验证记录见 §4.2、§13.1。

### 4.2 两个入口，一个引擎

```text
人类 Client ── Host Fetch ──┐
                           ├── applyOperations(document, baseVersion, ops, author)
AI 工具 ── Host 入口 ──────┘
```

Host 注册需要认证、仅 owner 可访问的精确 Fetch 路由：`POST /api/intent-canvas/read` 与 `POST /api/intent-canvas/apply`，分别接收 `{doc}` 与 `{doc, baseVersion, ops}`。Client 优先使用 `window.__DSH_TRANSPORT__.fetch`，不存在时回退到全局 `fetch`，请求相对地址 `api/intent-canvas/read` 与 `api/intent-canvas/apply`。响应直接是业务 JSON：成功为 `{ok:true, document, ...}`，失败为 `{ok:false,error:{code,message}}`，不是 RPC envelope，也不解包 `{ok:true,value}`。文档输入默认 `canvas`。

`author` 不由 Client 请求提供；Host 负责认证来源，不能信任 AI 在参数里自称 human。持久化位置、工具包装与安装配置以 Host 实现为准。

### 4.3 同步方式

Client 约每 1.1 秒读取文档，并在窗口重新获得焦点时刷新。仅版本变化时替换文档；正在拖动、保存或编辑文字时不接收轮询快照。读取响应也会检查文档身份和请求代次，避免旧响应覆盖新文档。

当前没有 presence 流、SSE、文件 watcher 接入或逐点远端播放。AI 已提交的编辑在后续有效读取时显示。

## 5. 操作与并发

### 5.1 操作族

| 类别 | 操作 |
|---|---|
| 图元 | `create`, `update`, `delete`, `move`, `resize` |
| 笔迹 | `create` 创建 `kind:'path'` 元素、`update` 修改 path、`erasePath` 局部擦除 |
| 结构 | `group`, `ungroup`, `reorder` |
| 语义 | `setText`, `setRole`, `setVariant` |
| 编辑 | `duplicate`, `paste`, `align`, `distribute` |
| 升维 | `promote`，咨询流程见 §6.7 |
| 批注 | `annotate`, `resolveAnnotation` |
| 待定 | `raisePending`, `resolvePending` |
| 历史 | `undo`, `redo`, `revertTo` |

### 5.2 引擎调用

```text
applyOperations(document, baseVersion, ops, author)
  -> {document, version, applied, diff, fragments}
```

- 引擎在克隆状态上应用整个批次；任一操作失败，整批不提交。
- `baseVersion` 不一致返回 `VERSION_CONFLICT`，不做静默合并或自动覆盖。
- Client 显示错误，可重新读取后由人重试；不会自动重放失败动作。
- 成功操作增加版本；错误类别包括 `VALIDATION`、`NOT_FOUND`、`VERSION_CONFLICT`、`HISTORY_UNAVAILABLE`、`FORBIDDEN`。

### 5.3 历史

撤销与重做针对**文档整体的批次历史**，不按作者跳过中间操作。AI 与人类必须理解：撤销可能影响另一方最近提交的批次。

`undo`、`redo`、`revertTo` 必须各自独占一个操作批次。引擎保留有限历史与 future（当前上限各 100），并非无限日志或任意历史重放服务。

### 5.4 视图与权限

选区、平移、缩放、网格和未提交轨迹为 Client 本地状态；当前没有选区共享或 AI `focus` 高亮通道。

当前没有“删除超过 5 项”或“回退超过 10 个版本”的确认阈值。不要把这些未实现的软闸当成保护。咨询批准是独立权限约束，见 §6.7。

## 6. 几何与笔迹

### 6.1 坐标约定

```json
{
  "id": "s7",
  "kind": "path",
  "rect": [120, 80, 30, 20],
  "points": [[0, 0], [8.5, 6], [30, 20]],
  "stroke": "#356c59",
  "strokeWidth": 2.5,
  "fill": "none"
}
```

- `rect` 为世界坐标 `[x,y,width,height]`；宽高非负，坐标可为有限小数，并非整数栅格。
- 即使元素有 `parent`，它的 `rect` 仍是**世界坐标**，不是父组局部坐标。
- path 的 `points` 为相对于自身 `rect` 原点的局部坐标。世界点 = `rect` 原点 + 局部点。
- `move` 平移 rect；分组后移动后代一次，不重复平移。
- `resize` 会缩放图元几何、后代世界 rect 和 path 的局部 points；不是只改包围盒而永久保留原始点。
- 显示变换由视口的平移与缩放完成，不写回文档坐标。

### 6.2 采集与渲染

Client 从指针事件采集折线，按当前缩放过滤距离过近的点（约 0.9 屏幕像素），并优先消费 `getCoalescedEvents()` 的子帧采样；单次手势采集上限为 3000 点。渲染时用 Catmull-Rom 把折线转成三次贝塞尔：普通、马克笔、铅笔、水彩为圆端平滑曲线；钢笔（以及带压感的触控笔）走变速宽度的实心轮廓并补圆端，抬笔与落笔不再出现折角。

压感只在 `pointerType === 'pen'` 时写入可选的 `pressures` 数组（与 `points` 等长，0.05–1），鼠标轨迹不写入。当前没有实现 RDP 简化；引擎允许的单 path 点数上限为 10000，与 Client 单次采集上限不同。

### 6.3 局部橡皮

```text
erasePath { id? | ids?, points: [[worldX,worldY], ...], radius }
```

- 橡皮轨迹 points 和 radius 都使用**世界坐标单位**；不是 path 局部点。
- 不提供目标 id 时，引擎处理文档中的 path，不擦除普通矩形、文字或便签。
- 引擎按圆/胶囊区域精确裁剪线段，生成保留碎片，而非依靠固定采样步长判定。
- 第一个保留碎片沿用原 id；其他碎片使用新 id。样式和 parent 保留，rect 与局部点重新计算。
- 完全擦掉的 path 被删除；结果通过 `fragments` 描述碎片映射。

拖动时仅用本地 SVG mask 和扫掠轨迹预览；抬笔后提交一条 `erasePath`。`Esc` 或指针取消放弃本次轨迹，不改共享文档。一次扫过多条笔迹仍是一个批次、一步撤销。预览不是服务器裁剪结果的逐帧计算，也没有帧率保证。

### 6.4 选择与命中

普通图元按包围盒命中；path 先做包围盒预筛，再计算点到折线的距离。点击子元素时选择其顶层组。

框选使用包含关系；套索使用图元中心点在多边形内的判定。当前是遍历元素，没有空间索引、吸附或性能基准。

### 6.5 约束与资源限制

引擎限制包括：坐标绝对值不超过 `1e6`、文档元素不超过 10000、单 path 不超过 10000 点、单批次不超过 1000 条操作、JSON 深度不超过 30，并设有橡皮复杂度上限。限制用于拒绝过大或非法输入，不代表这些规模下已经验证交互性能。

### 6.6 笔迹读取

当前引擎快照包含元素与 path points。尚未实现“AI 永远只读六字段摘要”、闭合语义摘要、按 group 的 token 压缩或 `mark.*` 意图编译器。调用方应主动控制读取范围与上下文开销，不能假定这些优化已存在。

### 6.7 圈选与显式转化

Client 在绘制椭圆，或判定手绘线近似闭合后，显示咨询卡；套索选中内容也可显示分组咨询。手绘近闭合检查只用于触发提示，不声明已经识别真实语义。

咨询操作：

- **转成卡片**：对已绘制圈执行 `promote {id,to:'card',approved:true}`，修改该元素 kind；不自动建立带内边距的 frame 或重新挂载圈内元素。
- **编组圈内**：至少两个候选元素时执行 `group {ids,groupId}`；不自动删除原来的圈。
- **保留笔迹**：关闭咨询，不改文档语义。

当前 Client 的圈内候选按包围盒内的中心点选取；套索使用多边形中心点判定。它们都不是语义识别。

AI 可以提出 `raisePending`，或发起需要咨询的提升操作，但不能冒充人类批准。引擎对 ellipse/circle 的非人类批准提升生成开放咨询；`resolvePending` 的咨询批准要求可信的人类作者。AI 应提出意图并等待人类选择，不应利用其他 kind 绕开咨询。

## 7. 手势与提交

移动、缩放、绘图与橡皮的进行中状态仅在本地显示。抬笔才提交文档操作；`Esc` 放弃进行中状态。多人 presence、远端光标、逐点广播与 AI 绘制动画尚未实现。

## 8. 已实现页面操作

### 8.1 工具与视图

| 输入 | 行为 |
|---|---|
| `V/P/E/T/R/O/A/N/L` | 选择/画笔/橡皮/文字/矩形/椭圆/箭头/便签/套索 |
| `Space` + 拖动，或中键拖动 | 平移 |
| 滚轮 | 以光标为锚缩放 |
| 工具栏 Fit | 全览内容 |
| 工具栏 +/-、Grid | 缩放、点网格开关 |

笔宽滑杆为 1–12；橡皮半径控件为 4–60（视觉尺寸转换到世界单位提交）。缩放范围当前为 8%–800%，点网格间距为 24 世界单位。网格是视图辅助，不执行吸附。

### 8.2 编辑

| 输入 | 行为 |
|---|---|
| 点击、Shift 点击、空白拖框 | 单选、多选、框选 |
| `Ctrl/⌘+Z`、`Ctrl/⌘+Shift+Z` 或 `Ctrl/⌘+Y` | 撤销、重做 |
| `Ctrl/⌘+C/V` | 画布内部复制/粘贴，不是系统剪贴板 |
| `Ctrl/⌘+D` | 副本，默认偏移 20 世界单位 |
| `Ctrl/⌘+A` | 选择顶层元素 |
| `Ctrl/⌘+G`、`Ctrl/⌘+Shift+G` | 编组、解组 |
| `[`、`]` | 置底、置顶，不是逐层移动 |
| `Delete/Backspace` | 删除 |
| 方向键、Shift + 方向键 | 1/10 世界单位微移 |
| 右下角选择手柄 | 缩放选择与组后代 |
| 工具栏 | 对齐、分布、前后顺序、复制粘贴、批注 |

当前没有 Alt 拖副本、Shift 正圆/轴向约束、栅格吸附、F 全览键或 Ctrl+0 等视图快捷键。

### 8.3 多行文字

双击元素打开 textarea；文字/便签工具点击创建编辑框。不使用 `prompt()`。

- `Enter` 插入换行。
- `Ctrl/⌘+Enter` 或 Save 保存。
- `Esc` 或 Cancel 取消，不保存本次输入。
- 输入框内普通键盘操作与撤销交给输入框，不触发画布编辑快捷键。

画布快捷键绑定在画布根节点，不是全局监听；浏览器、composer 和其他面板的快捷键不应被画布抢占。

## 9. 文档形状

```json
{
  "id": "canvas",
  "version": 2,
  "elements": [
    {"id":"g1","kind":"group","rect":[0,0,300,180]},
    {"id":"e1","kind":"note","parent":"g1","rect":[20,20,180,100],"text":"待讨论","fill":"#f4e9ac"},
    {"id":"s1","kind":"path","parent":"g1","rect":[30,130,80,20],"points":[[0,0],[80,20]],"stroke":"#356c59","strokeWidth":2.5}
  ],
  "annotations": [],
  "pending": [],
  "history": [],
  "future": []
}
```

历史内容由引擎维护；示例空数组仅展示顶层字段。kind 不是文档中声明的封闭 UI 枚举；可有语义图元，但 Client 对不认识的 kind 主要按矩形/文字显示。颜色可使用实际 stroke/fill 值，不是仅限 variant。

## 10. AI 侧使用规则

1. 先读当前文档，再以其 version 为 baseVersion 提交操作。
2. 收到冲突后重新读取并重新判断，不自动覆盖，也不假定失败批次部分成功。
3. 改完回读确认；移动/缩放尊重世界 rect 与局部 path points 的区别。
4. 不修改稳定 id；语义转换使用专门操作。
5. 未确定意图使用 `raisePending` 或明确询问；咨询由人类批准。
6. 不假定能读取 Client 选区、实时笔迹或视口；这些尚未共享。

Host 的工具名称、参数包装和注入提示以其实际注册为准；本文不宣称已实现 `canvas_await_user`、`mark.*` 或会话图片提交按钮。

## 11. 页面组成

当前页面为：标题与文档输入、两排工具栏、SVG 工作区、咨询卡/文字编辑框、待确认条目、选中元素批注、版本与视图状态栏。侧栏提供画布入口。

尚无右侧语义检查器、会话引用 chip、作者归属面板或 composer dock 提示。

## 12. 视觉与可访问性

页面容器、文本、边框与状态优先使用 Host 主题变量，图形支持自选颜色。按钮带 title/aria-label，切换工具带 aria-pressed，错误使用 alert，保存状态提供 aria-live。

这些是实现措施，不等于完整可访问性审计。仍需在真实页面检查深浅色、窄屏、键盘顺序、指针捕获和焦点行为。

### 13.23 拖动/绘制的闪烁（2026-11-04，1.0.22）

- 反馈：每次拖动或绘制，整个画布和所有操作按钮都会闪一下。
- 原因：`pointermove` 是**每个鼠标事件**都 `setState`（`setGesture` 或 `setView`），鼠标一秒可发 120+ 次；每次都会让整个面板重渲染（几十个 SVG 图元 + 所有按钮），并触发整块重绘，看起来就是闪。
- 修法：手势与视图更新改为**每帧提交一次**。`pointermove` / 平移 / 滚轮缩放只更新 `live.current` 里的最新值，并用 `requestAnimationFrame` 合并提交（`queuePaint`），`cancelAnimationFrame` 在指针抬起时清理待处理帧。数据仍在手势结束时一次性提交，落库内容不变。
- 测试：30/30 通过（测试环境没有 `requestAnimationFrame`，回退为同步执行，行为与之前一致）。**未目视验证**：闪烁是否消失；若仍存在，下一步会把拖动预览改成只对选中元素加 `transform`、松手才重排整棵场景。

### 13.24 场景改为 Canvas 2D 渲染（2026-11-04，1.0.23）

- 反馈：不止拖动，画布上**任何**操作都会闪；用户倾向方案 C（Canvas 重写）。
- 渲染：`<svg>` 场景整体替换为 `<canvas>`。`paint()` 一次性完成「背景 → 网格点 → 所有图元 → 手势预览 → 选区框」，使用 `devicePixelRatio` 适配清晰度，`ctx.translate/scale` 承载视图变换。DOM 里不再有几十个 SVG 图元节点，任何交互都只重画一张位图。
- 具体实现：`drawEl(ctx,e,ink)` 按 kind 绘制（path / ellipse / arrow / rect / note / text，箭头手绘箭头尖，文字 `fillText` 16px）；`drawGesturePreview(ctx)` 画笔迹、形状预览、框选与橡皮轨迹（橡皮改为半透明红色笔迹，不再用 SVG mask）；颜色从 `getComputedStyle` 读主题变量并带十六进制回退。
- 交互不变：命中测试仍是几何计算（`pick`/框选/lasso 多边形），快捷键、撤销、咨询、文字编辑浮层、所有按钮逻辑未改。
- 八个拖拽把手改为 **DOM 覆盖层**（`.ic-handles > .ic-handle`，仍带 `data-resize` 与原光标），因此 `pointerDown` 的把手分支和现有测试都无需改动。
- 测试：30/30 通过；测试环境没有 `getContext`，`paint()` 直接返回，不影响处理函数测试。**未目视验证**：真实画面（字号、线宽、DPR 清晰度、深色主题对比度）需要刷新后确认。

### 13.25 手势期不再走 React（2026-11-04，1.0.24）

- 反馈：换成 canvas 后仍然闪，且画笔延迟肉眼可见。
- 原因：`pointermove` 仍会 `setState`（即使已按帧合并），一次手势等于每帧重渲染整个组件（浮动条、按钮、把手）再在 `useEffect` 里绘制——等于「两帧延迟 + 整棵组件重建」，画笔轨迹自然滞后。
- 修法：绘制彻底脱离 React。`pointermove` 只更新 `live.current`（doc/view/gesture/selection/color/width 等），然后 `requestAnimationFrame` 直接调用 `paint()` 画位图；**手势期间零次 React 渲染**，只有 `pointerdown` 与 `pointerup` 各一次。`paint()` 全部从 refs 读取，`rectWith(e,g)` 取代依赖 state 的 `visualRect`。
- 平移与缩放同样只改 ref 并直接重画；React 的 `view` state 改为去抖同步（150ms）并在指针抬起时立即同步，保证工具栏的百分比显示跟得上。
- 测试：30/30 通过（手势仍写入 `live.current.gesture`，提交逻辑未变）。**未目视验证**：延迟与闪烁是否消失。若仍闪，剩余怀疑点是面板自身的合成层（`box-shadow` / `container-type`），下一步会移除这些属性验证。

### 13.26 手势数据完全移出 React state（2026-11-04，1.0.25）

- 用户判断：绘制数据应该静态保存，不要走 `setState`，因为每次 `setState` 都会重渲染页面导致闪烁。
- 1.0.24 只把 `pointermove` 移出 state，但 `pointerdown` / `pointerup` 仍各有一次 `setGesture`，且空画布提示与拖拽把手层都依赖 `gesture` state，所以每次起笔仍会重渲染一次。
- 1.0.25 彻底移除 `gesture` state：它只保存在 `live.current.gesture`；`pointerdown` / `pointermove` / `pointerup` / `pointercancel` 全程 **0 次 setState**（只有写入成功的 `commit` 会 `setDoc` 一次）。
- 连带调整：空画布提示改为**在 canvas 上绘制**（不再依赖 state 判断）；拖拽把手层在按下时用 `display:none` 隐藏、抬起恢复（直接改 DOM，不进渲染）；画布光标只看当前工具。
- 测试：30/30 通过。**未目视验证**：是否彻底不闪；若仍存在，则与 React 无关，需检查宿主面板的合成层（`box-shadow`、`container-type`、`backdrop` 等）。

### 13.27 合成层与版本标识（2026-11-04，1.0.26）

### 13.28 隔离宿主无关重渲染（2026-11-04，1.0.27）

- 用户要求提高画布渲染独立性，避免绘图受到宿主更新干扰。
- 排查重点不在渲染技术（1.0.23 起已使用 Canvas），而在**独立性**：画布挂在 Harness 的 React 树里，宿主在流式输出、会话状态更新时可能连带触发画布子树重渲染和 `paint()`。
- 做法：把面板子树按会话缓存为**同一个 React 元素**（`panelFor(key)`），宿主重渲染时返回相同元素引用，React 跳过这棵子树；只有画布自身 `setState`（文档/选区/工具）时才重建。
- 之前几轮已做的：canvas 单独提层（`will-change`/`contain`）、去掉浮动条阴影、手势全程零 `setState`。
- 版本可见：左上角显示 `v1.0.27`，用于确认页面是否加载了最新构建。
- 测试：30/30 通过。**未目视验证**：这是目前最可能的根因，但仍需用户刷新后确认是否还闪。

### 13.29 修复选中后拖不动把手（2026-11-04，1.0.28）

### 13.34 擦不干净：半径补齐线宽（2026-11-04，1.0.33）

### 13.40 修复复制恒报 Nothing to copy（2026-11-04，1.0.39）

### 13.47 旋转柄点不动 & 反复缩放后失灵（2026-11-04，1.0.46）

- 反馈：① 点旋转柄后拖不动；② 对 6 号图元反复调高宽，多次之后不灵敏。
- 原因 ①：`.ic-handles` 是 `pointer-events:none` 的覆盖层，只有 `.ic-handle` 写了 `pointer-events:auto`；新加的 `.ic-handle-rotate` 漏了这一条，于是点击穿透到 canvas，被当成空白处框选——表现就是“旋转柄点了没反应”。
- 原因 ②：`resizeRect` 的最小尺寸是 1 个**世界**像素，反复向内拖会把图元压到 1px 以下，八个手柄彼此重叠、几乎无法再抓取，看起来就是越拖越失灵。
- 修法 ①：`.ic-handle-rotate` 补 `pointer-events:auto`。
- 修法 ②：缩放的最小尺寸改为 **8 个屏幕像素**（按当前缩放换算成世界单位），预览（`rectWith`）与提交（`pointerUp`）都用同一门槛钳制，图元不会再被压成无法抓取的细条。

### 13.48 第二次旋转失效：旋转柄改锚定旋转后的包围盒（2026-11-04，1.0.47）

### 13.49 松手后立刻再转失效：busy 窗口吞掉新手势（2026-11-04，1.0.48）

- 反馈：旋转一次松手后，紧接着再旋转不行；先在空白处点一下、再点回图元就又能转。
- 原因：每次旋转松手都会走一次 `commit`，期间 `busy` 为真。而 `pointerDown` 里有 `if(!doc||busy||...) return`，`commit` 里也有 `if(s.busy) return null`——第一次提交还在飞行时开始的第二次拖拽会被整个丢掉；等它空闲（点空白、重新选中）之后又正常，与现象完全吻合。
- 修法：① `pointerDown` 不再因 `busy` 拒绝开始手势；② `commit` 遇到 `busy` 先等上一次完成（最多约 1 秒）再提交，不再静默丢弃；③ 旋转柄锚定「旋转后包围盒」并夹在画布内，转完不会被裁掉；④ 新增 **Alt + 拖动选中图元 = 旋转**，不依赖小圆柄；浮条另有「左转/右转 90°」。
- 测试：41/41 通过（busy 时序在单测里不可复现，靠代码路径保证）。**未目视验证**：真实环境下连续两次旋转的手感。

### 13.54 根因：旋转提交读到旧闭包文档（2026-11-05，1.0.53）

- 反馈：① 导出按钮的气泡定位错，应该就在按钮正上方；② 拖拽旋转仍是“第二次没用”。

- 旋转根因：`pointerUp` 的旋转分支用闭包里的 `doc` 读基础角度。第一次提交完成后 React 还没重渲染，**紧接着**的第二次拖拽仍走旧闭包，读到的 `rotation` 还是 0，于是又算出 90°——画布上看起来“完全没动”。点空白再点回来之所以能好，是因为中间完成了一次重渲染，闭包拿到了新文档。

- 回归测试：新增「用同一批旧闭包连续旋转两次」的用例——第一次 90°，第二次必须累加到 360°/0°，证明不再被旧状态覆盖。

- 原因：textarea 的 `onBlur` 直接调用 `saveEditor()`；点击颜色选择器或字号下拉会让焦点从 textarea 移出，于是**blur 立即提交并关闭编辑器**，看起来就是“选中即消失”。
- 修法：给编辑器整体加 `editorRef`，blur 时先判断焦点去处——`relatedTarget` 在本卡片内就直接忽略；再用 `setTimeout(0)` 检查一次 `document.activeElement`（原生取色器打开时 `relatedTarget` 可能为空），仍在卡片内也不提交。只有焦点真正离开编辑器（例如点画布、点其它界面）才保存关闭。
- 测试：45/45 通过（blur 时序不在单测范围）。**未目视验证**：真实浏览器里取色器交互后的表现。

### 13.93 笔迹平滑、子帧采样与空闲重绘保护（2026-11-10，1.0.97）

- 反馈：参考 [TempCanvas](https://tempcanvas.com/zh/) 的灵活手感；尤其是没有任何操作时画布不应抖。
- 技术调查：TempCanvas 的“真实感”主要来自 Fabric.js 的对象模型 + `PencilBrush`（按距离 decimate 后用二次曲线平滑）+ 自绘钢笔/马克笔/铅笔轮廓；它并没有一套可以整体拔下来的独立画布引擎，而是 500KB 级的应用 bundle（内含 Fabric、p5.brush、QR 等）。整套替换会把本插件已有的 `canvas_apply` 操作引擎、撤销、版本冲突和 AI 协作模型推倒重来，收益与风险不成比例；因此只移植直接影响笔迹几何与采样频率的部分。未复制其压缩代码。
- 采样层：`pointermove` 优先消费 `getCoalescedEvents()`，把一帧内被合并的子帧样本全部写入；采集距离阈值从 1.5 降到 0.9 屏幕像素，单次手势上限 1500 → 3000。抬手位置若不在最后一个子帧样本中，会补一次去重后的外框事件，避免丢尾点。
- 渲染层：新增 `traceStroke`，用 Catmull-Rom → 三次贝塞尔重画中心线；普通/马克笔/铅笔/水彩共用平滑曲线。钢笔改为在平滑后的中心线上按原始采样速度生成左右轮廓并填充，端点补圆，不再有折线角。预览与落库后的元素共用同一函数，抬笔时不会出现“突然变平滑”的跳变。
- 压感：`pointerType === 'pen'` 时同步采集 `pressures`（与 `points` 等长，0.05–1）；普通画笔收到压感时也用变宽轮廓。鼠标的恒定 0.5 压感不写入文档，避免无意义字节。`pressures` 是可选字段，旧文档不受影响。
- 空闲稳定性：`paint(force)` 增加绘制 key（尺寸、文档版本、视图、工具、选区、笔型等）。宿主因流式输出等无关更新触发 React 重渲染时，不再重传同一张位图；手势、悬停、图片解码、网格/编号开关走强制重绘。实测空闲 8 秒内 `clearRect` 调用为 0，画布区域连续截帧像素差为 0。
- 交互修复：拖拽从浮层边缘起手时会选中整个页面的 UI 文本（截图中整条工具栏被蓝色选中）。`.ic-app` 统一 `user-select:none`，输入框与文本域恢复可选。
- 顺带修复：`index.js` 的 `canvas_apply` 描述里把 `kind:'path'` / `kind:'image'` 写进了单引号字符串，导致 Host 导入即语法错误；已去掉内层单引号。该问题在 1.0.96 工作树中已存在，此前未跑到 `node --check index.js`。
- 测试：73/73 通过；新增“子帧采样与压感写入笔迹”“空闲重渲染不重绘画布”两条。真实 Web GUI 加载 v1.0.97 后画了平滑曲线与钢笔线，导出 PNG 的墨迹 bbox 与文档 rect 一致；空闲 6 秒 `clearRect` 为 0，连续两帧画布区域像素差为 0。
- 未验证：真实数位笔/触屏、桌面端 GPU 合成层与高 DPI 下的目视效果；Catmull-Rom 在极尖锐折角处可能有 1–2 世界单位的过冲，当前未做界内钳制。

### 13.94 场景层 M1：scene / overlay 双画布（2026-11-10，1.0.98）

- 目标：先把“已提交场景”和“手势预览/选择框/编号”拆成两张同尺寸画布，视觉与 1.0.97 保持一致，再在 M2 换单一指针管线。
- 结构：`scene` 画背景、网格、已提交图元；`overlay` 画手势预览、选择框、橡皮光标、编号、空画布提示。指针只绑在 overlay，scene 设 `pointer-events:none` 且不接事件；8+1 把手本阶段仍留在 DOM，M2 再迁入画布。
- 调度：`queuePaint('overlay')` 只清 overlay；笔、橡皮、框选、套索的 move 走这条路径；平移、缩放、移动/缩放/旋转仍走全量（scene 要按 `rectWith` 预览）。`paint` 的绘制 key 拆成 scene/overlay 两份，互不牵连。
- 实测：在 `m1-scratch` 上画 90 步曲线，手势期间 `scene.clearRect` 为 0（仅切换文档时 1 次），`overlay.clearRect` 91 次；空闲 5 秒两层均为 0；缩放两次 scene +2。网格/编号开关当前仍全量一次，M2 再按依赖收窄。
- 测试：74/74，新增“scene/overlay 分层与事件归属”一条。
- 下一步 M2：把把手、命中、光标、平移缩放迁入 overlay 与单一指针管线，去掉 DOM 把手和双时钟。

### 13.95 场景层 M2：画布内把手与单一指针管线（2026-11-10，1.0.99）

- 目标：去掉 DOM 把手层和 150ms 的视图滞后，让选择框、8 向把手、旋转柄、命中与光标都跟画布同一帧。

### 13.96 场景层 M3：视口退出 React 状态（2026-11-10，1.0.100）

- 问题：`view` 仍是 `useState`，平移/缩放经 `syncView` 150ms 才 `setState`。M2 的把手虽已画进 canvas、不再等它，但缩放百分比、文本编辑器、右键菜单的世界坐标仍依赖这份滞后状态，每次 `setState` 还会重渲染整个面板。
- 改法：`view` 改为 `viewRef` 单一真源。canvas、选择框、把手、命中、`pick` 的 5px 容差、橡皮半径、resize 最小尺寸、右键菜单、粘贴落点全部读 `live.current.view`。
- 缩放百分比改为 `zoomLabel` ref 直接写 `textContent`；`zoom()`/`fit()` 不再 `setState`。文本编辑器在打开时快照 `{...live.current.view}`，用自己的快照定位，不随全局视图变化。
- 删除 `syncView`、`viewTimer`，以及平移抬手时的 `setView`。
- 验证：按钮缩放后 80ms 读缩放标签已到 193%；平移抬手立即截帧与 500ms 后截帧，画布区域像素差 **0**（只有侧栏状态点变化）；空闲 5 秒两层 0 重绘；74/74。
- 未验证：多指触控缩放（当前只有滚轮/按钮）；缩放中的文本编辑器（滚轮被编辑器拦截，按钮缩放时编辑器保持旧位置）。

### 13.97 场景层 M4：变换手感（2026-11-10，1.0.101）

- 修复 M1 的一个回归：`pointerMove` 把所有非笔迹手势都送进 `queuePaint('overlay')`，导致**移动/缩放预览时元素本体不动、只有选择框在动**。现在 `move`/`resize` 走全量绘制，矩形/椭圆/箭头/框选/套索仍只画 overlay。
- 旋转框随手势旋转：`selectionChrome` 把当前 `rotate` 手势的角度叠加到元素的存储角度上，拖动过程中选择框、把手和元素本体保持同一角度；松手后落库角度不变。
- 修饰键：
  - 新建矩形/椭圆/半圆时按住 Shift → 正方形/正圆；
  - 移动时按住 Shift → 锁定水平/垂直（取位移较大的轴）；
  - 角把手缩放时按住 Shift → 保持原宽高比（按世界坐标计算，提交 op 不变）。
- 测试 **75/75**，新增一条覆盖上述三种 Shift 约束的用例。
- 未解决：顶部参数条、底部选中操作条仍可能压住正好落在它们下面的把手；旋转后再用 Shift 缩放仍按未旋转的包围盒计算，极端角度下会有偏差。
- 未验证：真实鼠标按住 Shift 的目视（自动化测试只覆盖事件层）、触屏。

## 14. 已知边界与后续方向

目前没有跨机器性能基准、空间索引、选区共享、presence、流式广播、语义摘要压缩或外部文件编辑合并；`perf-500` 只是单机粗略数据，不是 60fps 承诺。可以按真实使用反馈增加，而不是把规划当成已交付。

大文档和历史快照会增加内存/存储开销；当前依赖输入限制与有限历史，仍需测量。安全依靠原子校验、版本冲突、历史恢复和可信咨询批准，而不是未实现的数量阈值。

## 15. 总结

当前核心是**同一文档、同一操作引擎、显式版本、局部擦除与明确的人类意图确认**。界面已具备基础编辑工作流；安装集成、真实浏览器交互与性能应分别验证，不能由设计稿或模拟测试推定。
